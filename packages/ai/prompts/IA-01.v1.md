# IA-01 · Mapa de temas de un documento

## Variables

- `cliente`
- `glosario`
- `proyecto.tema`
- `proyecto.publico`
- `proyecto.metaMinutos`
- `proyecto.objetivos (opcional)`
- `documento.id`
- `documento.nombre`
- `documento.rango`
- `documento.texto_por_pagina`

## Sistema

```text
{{> _comun}}

Actúas como diseñador instruccional sénior que lee documentos técnicos largos y detecta qué enseñar.
```

## Usuario

```text
Tarea IA-01: arma el mapa de temas del documento.

Proyecto: {{proyecto.tema}} · Público: {{proyecto.publico}} · Meta: {{proyecto.metaMinutos}} minutos.
Objetivos dados por el cliente (pueden faltar): {{proyecto.objetivos}}

Instrucciones:
- Divide el documento en temas enseñables (entre 5 y 25). Un tema = algo que el
  participante debe saber o hacer. Agrupa páginas administrativas (índice,
  control de cambios, firmas) en un solo tema de tipo "otro" con peso 1.
- Para cada tema: título corto (máx. 8 palabras), resumen fiel de 1 a 2 frases,
  páginas exactas donde aparece, tipo de contenido y peso 1-5 según su
  importancia para este público y esta meta de tiempo.
- Marca con peso 5 las advertencias de seguridad, pasos obligatorios y normas.
- Si hay objetivos del cliente, relaciona cada tema con los objetivos que cubre.
- Las páginas vienen marcadas como [p. N]; usa esos números.

<material_cliente archivo="{{documento.nombre}}" paginas="{{documento.rango}}">
{{documento.texto_por_pagina}}
</material_cliente>

Formato de salida: JSON que valida contra IA-01.salida.schema.json. documentoId = "{{documento.id}}".
```

## Criterios de calidad (los revisa el diseñador)

- Ningún tema sin páginas.
- Las advertencias y pasos obligatorios del documento aparecen todos.
- Los títulos se entienden sin leer el documento.

## Notas para desarrollo

- Documentos de más de ~150 páginas: dividir en bloques de 60 páginas, ejecutar por bloque y unir temas con el mismo título.
- Enviar el esquema de salida a la API como herramienta (tool use) con `input_schema` = esquema **empaquetado** (resolver los `$ref` al esquema del curso antes de enviarlo) y forzar esa herramienta; luego validar igual con Ajv.
- Si no valida: reintentar hasta 2 veces agregando al mensaje los errores de Ajv (ruta y mensaje). Si sigue fallando, la etapa queda en ERROR (RN-04-2).
- Registrar en `TrabajoIA`: tarea, versión de este archivo, modelo, tokens de entrada y salida, costo, duración y resultado.
- Variables con `{{ }}`: las llena `packages/ai`. Los textos del cliente siempre dentro de `<material_cliente>`.
- Cambiar este prompt = nueva versión (`.v2.md`) y pasar los casos de referencia (`packages/ai/casos/`) antes de usarla en producción.
