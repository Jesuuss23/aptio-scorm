# IA-04 · Estructura del curso (v2)

Cambios respecto a v1 (HU-0403, CP-039): pide el número exacto de pantallas y el mínimo de pantallas con actividad
según el % del proyecto, y entrega los fragmentos dentro de `<material_cliente>` porque vienen del documento del cliente.

## Variables

- `cliente`
- `glosario`
- `proyecto.tema`
- `proyecto.publico`
- `proyecto.nivel`
- `proyecto.metaMinutos`
- `proyecto.pantallasMeta (sin valor, la IA propone la extensión)`
- `proyecto.porcentajeActividades`
- `proyecto.actividadesMinimas (pantallasMeta × % redondeado hacia arriba)`
- `proyecto.objetivos (opcional)`
- `fragmentos (salidas IA-03)`
- `gamificacion (sí/no)`

## Sistema

```text
{{> _comun}}

Actúas como diseñador instruccional sénior experto en microaprendizaje y taxonomía de Bloom.
```

## Usuario

```text
Tarea IA-04: define objetivos y la lista de pantallas.

Tema: {{proyecto.tema}} · Público: {{proyecto.publico}} · Nivel: {{proyecto.nivel}}
Duración: {{proyecto.metaMinutos}} min · Pantallas: exactamente {{proyecto.pantallasMeta}} en total
Pantallas con actividad: al menos {{proyecto.actividadesMinimas}} ({{proyecto.porcentajeActividades}} % del total)
Objetivos del cliente (si hay, respétalos y solo ajusta el verbo): {{proyecto.objetivos}}
Fragmentos disponibles (ideas clave del material, con su página):
<material_cliente archivo="ideas clave de la etapa 1">
{{fragmentos}}
</material_cliente>

Reglas:
- De 2 a 4 objetivos medibles, con un verbo de Bloom en infinitivo
  (identificar, distinguir, aplicar…). Al menos uno de nivel "aplicar" o superior
  si el público es operativo.
- Estructura recomendada de una cápsula: portada → objetivos → presentación del
  personaje → secciones (seccion + contenido + actividad) → resumen → reto final
  (evaluacion) → resultados → cierre.
- Cada sección cierra con una actividad. Al menos 1 actividad cada 4 pantallas.
- Cuenta como pantalla con actividad la de tipo "actividad" o "evaluacion", o la que
  lleva actividadSugerida. Cada una se liga al menos a un objetivo, y cada objetivo
  tiene al menos una actividad.
- Si no se indica el número de pantallas, propón la extensión según el material.
- fragmentoIds solo usa ids de la lista de fragmentos.
- Cada pantalla de contenido o actividad indica los objetivos y fragmentos que usa.
- Sugiere la actividad (INT-01..08) según el objetivo: memoria o tarjetas para
  recordar; clasificar o deslizar para distinguir; ordenar para procedimientos;
  decisión o exploración para aplicar; quiz para el reto final.
- Ids de pantalla: p01, p02… en orden.

Formato de salida: JSON que valida contra IA-04.salida.schema.json.
```

## Criterios de calidad (los revisa el diseñador)

- Cada objetivo tiene al menos una actividad y una pregunta del reto final.
- Ninguna pantalla de contenido sin fragmentos (salvo portada, objetivos, personaje, sección, resultados y cierre).
- Número exacto de pantallas y mínimo de pantallas con actividad (se validan solos, ver `apps/worker/src/etapas/estructura.ts`).
